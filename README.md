# PS 自动化套图工具

Windows 桌面工具：连接当前已经打开的 Photoshop，批量识别 PSD、PSB、TIF/TIFF 模板中的智能对象，替换素材并导出 JPG 或 PNG。

## 工作流程

1. 启动 Photoshop，再启动本工具。工具只连接当前正在运行的 Photoshop；识别不到实例时会提示，不会自动启动或切换版本。
2. 选择单模板或多模板，设置模板、素材文件夹和输出目录。
3. 输入智能对象识别关键词，或点击“提取智能对象”。文件夹模式默认读取排序后的第一个模板，提取不会保存模板改动；提取结果会自动过滤 `tag` 智能对象及其副本，并合并同一对象的 Photoshop 副本。
4. 在“图层映射”中为每个智能对象填写图号。图号从 1 开始，对应素材自然排序后的第 N 张；`0` 表示跳过。
5. 点击“添加到队列”。任务会固化自己的模板路径、素材路径、输出路径、映射、指定尺寸和导出参数；之后修改表单不会影响已入队任务。可逐条删除或清空等待任务。
6. 开始套图。程序先识别全部模板，全部成功后才批量替换和导出；进度、日志和错误显示在右侧。

未填写智能对象名称时，会模糊识别图层序列，支持 `1/2/3/4`、`01/02/03/04` 与 `一/二/三/四`。相同序号只保留一个替换槽；无可识别序列时沿用历史关键词/图案槽位识别规则。

## 模板、素材与任务模式

界面中的“单模板 / 多模板”和“制衣模式”是两个独立维度：前者决定模板怎样组织，后者决定模板组与素材组怎样配对和执行。因此共有四种可用组合。

| 组合 | 适用场景 | 队列生成与执行方式 |
| --- | --- | --- |
| 单模板 + 普通模式 | 单个版型或多个独立版型，按素材批次分别出图 | 按索引配对模板组和素材组 |
| 多模板 + 普通模式 | 一套尺寸/颜色模板配一批素材，保留各模板输出目录 | 按索引配对模板组和素材组；同组模板依次处理 |
| 单模板 + 制衣模式 | 一个版型按每个产品素材文件夹连续生产 | 素材优先；每个素材组处理全部单模板组 |
| 多模板 + 制衣模式 | 每个产品素材文件夹需要套入一套多尺寸/多款 PSD | 素材优先；每个素材组处理全部产品模板组，并输出到产品目录 |

### 1. 选择和分组规则

- **单模板**：选择一个或多个 `.psd`、`.psb`、`.tif` 或 `.tiff` 文件。每个文件都是一个独立模板组，即使一次选择多个文件，后续也会分别成为独立队列任务。
- **多模板**：选择一个模板文件夹。若该目录顶层包含模板文件，顶层全部模板组成一个模板组；若顶层没有模板，则扫描其直接子目录，每个包含模板的子目录组成一个模板组，目录名即产品名/任务名。不会跨更深层目录递归组合。
- **素材文件夹**：若所选根目录本身包含图片，根目录是一个素材组；其每个直接子目录只要包含图片，也各自成为一个素材组。根目录和子目录均按自然顺序排序，例如 `TX002` 在 `TX010` 前。
- 模板支持 `.psd`、`.psb`、`.tif`、`.tiff`；素材支持 JPG/JPEG、PNG、WEBP、TIF/TIFF、BMP，均按自然排序读取。

### 2. 普通模式：按索引配对

普通模式适合“模板批次”与“素材批次”一一对应的工作。程序按模板组、素材组的排序位置配对，任务数取两者中较大的数量：

- 两边数量相同：第 1 组配第 1 组、第 2 组配第 2 组，依此类推。
- 模板组更多：后续模板组复用最后一个素材组。
- 素材组更多：后续素材组复用最后一个模板组。
- 相同的“模板组 + 素材组”组合只保留一项，不会重复加入相同任务。

例如有模板组 `产品A`、`产品B`，素材组 `TX002`、`TX003`，普通模式生成 `产品A × TX002`、`产品B × TX003` 两项任务；若只有 `产品A` 一个模板组，则生成 `产品A × TX002`、`产品A × TX003`。

### 3. 制衣模式：素材优先的全组合流程

制衣模式适合按产品素材文件夹轮换：先完成一个产品素材的全部模板，再处理下一产品。它不使用普通模式的索引配对，而是生成“每个素材组 × 每个模板组”的组合，执行顺序固定为素材优先：

```text
素材/TX002/ → 产品A 的全部模板 → 产品B 的全部模板
素材/TX003/ → 产品A 的全部模板 → 产品B 的全部模板
```

例如模板目录含 `产品A/S.psd、M.psd、L.psd` 与 `产品B/S.psd、M.psd`，素材目录含 `TX002`、`TX003`：制衣模式依次执行 `TX002 × 产品A`、`TX002 × 产品B`、`TX003 × 产品A`、`TX003 × 产品B`。每个模板内部会先依照图层映射完成一轮替换，再导出，不会在每替换一个智能对象后导出。

### 4. 指定尺寸（多模板）

选择多模板文件夹后，工具会从模板文件名（不含扩展名）生成“指定尺寸”下拉多选项。可勾选一个或多个，勾选会在关闭下拉或加入队列时提交到任务快照；未选择表示使用该模板组中的全部模板。

- 优先按完整模板名精确匹配。
- 为兼容旧配置，也支持 `XS/S/M/L/XL/XXL/XXXL/XXXXL`、`均码/大码/中码/小码` 等尺寸词匹配。
- 队列会保存所选值；运行前会再次用该快照过滤多模板任务。找不到匹配模板时会明确报错并列出可用模板名。
- 单模板不使用指定尺寸过滤。

### 5. 从映射到一轮套图

图层映射决定每一轮如何消耗素材：最大非零图号就是该轮需要的素材张数。比如映射为 `后 → 01`、`前 → 02`、`左袖 → 03`、`右袖 → 04`、`领外 → 05`、`领内 → 06`，自然排序后的第 1 至第 6 张素材会依次替换对应智能对象，六个对象都完成后才导出一次。素材不足完整一轮时，尾部素材会跳过。

图号 `0` 会占住对应的 PSD 图层位置以防后续映射错位，但不替换图层、也不增加每轮素材数量。图号可以不连续，例如 `前 → 01`、`后 → 03` 会在每轮取第 1 张和第 3 张，并以最大图号 `3` 作为一轮跨度。若没有手动输入智能对象名称，工具会尝试识别名称中的 `1/2/3/4`、`01/02/03/04`、`一/二/三/四` 等序列；相同序号只保留一个替换槽位。

### 6. 单项任务的内部执行阶段

每个等待中的队列任务按以下阶段运行：

1. 校验模板、素材、输出目录与图层映射，并连接当前已经启动的 Photoshop。
2. 前置识别任务内全部模板，建立每个模板的智能对象槽位计划；前置识别失败时不会带着不完整映射继续批量导出。
3. 按“最大图号”切分素材轮次。每轮先把全部映射智能对象替换完成，再更新制衣模式的 `tag` 内容。
4. 极速模式尽量让模板只打开一次，并缓存可编辑智能对象；每轮结束后恢复干净状态再进入下一轮。无法使用缓存的模板自动退回兼容替换流程。
5. 根据 Web 切片开关走 Save for Web 或 Photoshop“存储为”，按当前 JPG/PNG、品质、基线、切片、缩放和对齐设置导出。
6. 当前项完成后更新队列状态并进入下一项；整轮队列结束后合并生成一份队列日志。状态为“完成”的旧任务不会再次执行，失败或取消的任务可以重试。

## 图层映射

映射使用“智能对象名称 + 图号”的强绑定，例如：

```text
前，后，左，右
01，02，03，04
```

映射编辑区显示 `前 → 01`、`后 → 02` 等独立控件。每个卡片右上角可删除，卡片支持拖拽排序；删除或拖拽后，非 `0` 图号会按当前顺序自动重排。执行时严格按卡片顺序为每一行创建独立槽位：先精确匹配一个尚未使用的同名智能对象，再尝试模糊匹配；同名重复对象和未写入映射的额外对象保持不变。`0` 保留并占用对应图层位置，但跳过替换，避免后续映射错位。

例如 `后 → 01`、`前 → 02`、`左袖 → 03`、`右袖 → 04`、`领外 → 05`、`领内 → 06` 会在同一轮中依次完成六次替换，然后只导出一次结果；PSD 中夹在这些图层之间的 `QR` 等未映射智能对象不会参与替换。

### 提取与过滤规则

“提取智能对象”会递归读取 PSD 图层，但只把需要人工套图的对象写入图层映射。名称以 Photoshop 自动生成的副本后缀结尾时会归一为原名：`Layers1`、`Layers1 拷贝`、`Layers1 副本 2`、`Layers1 copy 3` 最终只显示一条 `Layers1`；不论层级或副本数量，归一后名称为 `tag` 的对象均不会显示在映射中，继续由内置 tag 流程处理。运行时仍优先定位原始同名对象，副本保持不变。

图号可不连续，例如 `前 → 01`、`后 → 03`；程序严格取每轮第 1 张和第 3 张素材。每轮素材数量按最大图号计算，尾部不足一轮的素材自动跳过。

## 导出结构

以下结构中的“批次名”由本轮参与替换的素材名组成：只有一张时为该素材文件名（不含扩展名），多张时以 `__` 连接。普通模式文件名为 `模板名称_01.jpg`、`模板名称_02.jpg`；编号来自画布的自动切片顺序。格式后缀由 JPG/PNG 设置决定。

### 单模板 + 普通模式

```text
输出目录/
  模板名称/
    批次名/
      模板名称_01.jpg
```

### 多模板 + 普通模式

```text
输出目录/
  模板组名称/
    批次名/
      模板名称A/
        模板名称A_01.jpg
      模板名称B/
        模板名称B_01.jpg
```

普通多模板在实际执行的模板数大于 1 时会保留模板子目录，避免同一组中不同 PSD 的切片同名而互相覆盖；若指定尺寸过滤后只剩一个模板，则直接写入批次名目录。

### 单模板 + 制衣模式

```text
输出目录/
  素材文件夹名_尺码.jpg
```

### 多模板 + 制衣模式

```text
输出目录/
  产品文件夹名/
    素材文件夹名_尺码.jpg
```

制衣模式不再增加批次名目录或模板子目录。多模板制衣的“产品文件夹名”取模板组目录名，绝不会用素材名创建产品目录；尺码优先从模板文件名识别，识别不到且只指定了一个尺寸时才使用该指定值。为避免同目录文件互相覆盖，同一产品组内应保证各模板最终识别出的尺码名称唯一。启用“保留整张合并图”时，会在同一目录额外生成同名的 `_merged` 文件。

## 导出设置与性能

- JPG/PNG 可独立选择，与导出方式无关。
- 界面默认关闭 **Web 切片**，也就是先走 Photoshop“存储为”；开启后才切换到 Web 切片导出。Web JPG 品质范围为 0–100。
- 关闭 Web 切片时使用 Photoshop“存储为”；JPG 通用品质范围为 1–12，基线可选“标准/优化”。PNG 仍按 PNG 保存。
- 普通“存储为”导出会在 JSX 与 Python 收尾阶段刷新当前运行时间、XMP 创建/修改时间和 Windows 文件时间，避免沿用 PSD 模板的创建时间。
- “保留整张合并图”只额外保留完整画布，不改变切片规则。
- 缩放支持裁切填满、拉伸、锁定宽度、锁定高度；关闭“自动对齐”后可用手动对齐按钮覆盖自动规则。
- 性能模式固定为极速：每个模板尽量只打开一次，批次间恢复干净状态并复用可编辑智能对象；相同 tag 智能对象只更新代表对象。

## 队列、日志与配置

每个队列任务独立保存模板路径、图层映射名称与图号、指定尺寸、素材路径、输出路径、JPG/PNG、Web 切片、品质、基线、缩放、对齐和合并图设置。完成的任务会保留在队列中显示为 `完成 / 100%`，后续添加任务并再次开始时只执行等待、失败或已取消的任务，绝不重复执行已完成任务；队列标题同时显示总数和待执行数量。日志以本轮实际执行的全部任务完成为准统一写入，不单独永久保存每项任务日志；右侧行进度解析同一队列日志中的当前任务段。运行中可取消，程序会尽量安全关闭临时文档并写入最终状态。

保存的智能对象配置强制关联模板路径与非空图层映射，并保存模板文件夹、识别关键词、映射、指定尺寸、制衣模式和指定尺码。切换配置会同步恢复这些参数；旧配置没有 `smart_mappings` 字段时，按旧关键词顺序兼容生成 1、2、3……默认图号。

## Photoshop 与设备兼容性

- Windows 10/11，打包版为 64 位程序。
- 支持可运行 ExtendScript/JSX 的 Photoshop CS6 与 CC 系列，并兼容常见新版 COM 参数差异。
- 优先使用当前实例公开的 `DoJavaScriptFile`/`DoJavaScript`；必要时使用当前运行 Photoshop.exe 执行临时 JSX。
- 多个 Photoshop 同时运行且 COM 无法区分实例时会停止并提示，不会猜测目标版本。
- 临时 JSX 使用 UTF-8 BOM，支持中文图层名、中文用户名和中文路径。
- 工具与 Photoshop 应使用同一权限级别；若 Photoshop 以管理员身份运行，本工具也应以管理员身份运行。

## UI 设计规范

界面采用 Liquid Glass 方向：蓝白/深蓝玻璃卡片、渐变背景、轻量高光边框和统一圆角。顶部仅保留产品名称和主题控件；主题按钮使用 Microsoft YaHei UI 和 Microsoft Fluent Emoji 开源彩色 SVG 转换图标，不使用 emoji 作为结构化按钮文字。默认窗口 `1280 × 800 px`，最小窗口 `1024 × 680 px`；窗口较窄时自动改为上下布局，所有卡片、队列、日志和映射控件均可伸缩，避免重叠遮挡。

图标资源位于 `src/ps_auto_suite/assets/icons/`，来源为 [Microsoft Fluent Emoji](https://github.com/microsoft/fluentui-emoji)，遵循其开源许可。

## 开发、测试与打包

```powershell
cd PS-auto-suite-tool
python -m pip install -r requirements-dev.txt
$env:PYTHONPATH = "$PWD\src"
python -m py_compile src/ps_auto_suite/app.py src/ps_auto_suite/photoshop_runner.py src/ps_auto_suite/task_queue.py
python -m pytest -q
.\scripts\build.ps1
```

打包工作软件：

```text
dist/PS-Auto-Suite-Tool.exe
```

发布构建使用 Nuitka 将 Python 业务代码编译为原生二进制，再生成单文件、无控制台 EXE；界面资源、Tk、CustomTkinter 和 Photoshop COM 依赖会一并收集。构建缓存位于 `.nuitka-build/`，最终只分发 `dist/PS-Auto-Suite-Tool.exe`。
